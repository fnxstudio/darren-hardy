Champion Board CMS Sync

Your card.darrenhardy.com console already syncs referral IDs and referred sales from HubSpot every hour. This spec adds one step to that job: write each Champion's numbers into the Webflow CMS that powers the Champion Board on thecompoundeffect.com.

Site thecompoundeffect.com Site ID 6aa109c0730dcec4155908e1 Page thecompoundeffect.com/champion Updated Oct 14, 2026

Where it stands today. The board is live at thecompoundeffect.com/champion. It is hidden from search engines and no Champion has the link yet.

Darren Hardy is showing it live at the event, so for now every seat on the board is a placeholder named "Your Name Here". Real Champions go in after the event, from the people who sign up there. Your sync is what fills it.

The short version

  1. Every hour, after your HubSpot sync, pull each Champion's referral ID, name, email and impacts.
  2. Work out rank, level and the status line using the rules below.
  3. Create or update their record in the Champions collection. The record's slug is their referral ID in lowercase.
  4. Write a sign-in key for their email into Champion Logins.
  5. Rewrite the Board Pages text that feeds the full standings list.
  6. Publish the changed items. No site publish is needed.

The referral ID is the one your console already creates from HubSpot. It must be the same everywhere: the mailer QR, the Spiffy utm_content and this board. The board's share links already carry it as utm_content so referred sales credit the right Champion.

Access

Use a Webflow site API token, not anyone's Webflow login. We generate it in Site settings → Apps & integrations → API access with CMS: read and write only, and send it to you privately. It can be revoked at any time.

API base: https://api.webflow.com/v2. Send the token as Authorization: Bearer <token>. Reference docs: developers.webflow.com/data/reference/cms.

Levels

Seat counts are not fixed in the script. Each run reads the Champion Levels collection (6ad776ab90f1167d6dedc395): one record per level with level (1 to 4) and min-seats. A Champion's level is the highest one whose min-seats they have reached. Our team can change the seat counts or names at any time and the next run re-levels everyone. The script stops with a clear error if the records don't add up (gaps in the numbering, or a level that needs no more seats than the one below).

Rank

Sort by impacts, highest first. Ties go to whoever reached their current count first, so you need the timestamp of each Champion's latest credited seat. Earlier timestamp ranks higher.

Move this week

Save every Champion's rank once a week (Monday 12:00 am ET). move-this-week = snapshot rank - current rank. A new Champion with no snapshot gets 0.

2. Champion Logins

Collection ID 6acf13c97a9a39ec5acbee1a. One record per sign-in email. When a Champion types their email on the board, the page hashes it in the browser and looks for this record. No email is ever published on a page.

Field slugWhat goes in it
slugFirst 40 hex characters of SHA-256 of the email, trimmed and lowercased.
refTheir referral ID (same value as champion-id).
nameAnything readable for our team, e.g. "Brenda Huntley". Shown nowhere.
 
// Node
const key = require('crypto').createHash('sha256')
  .update(email.trim().toLowerCase()).digest('hex').slice(0, 40);

# Python
key = hashlib.sha256(email.strip().lower().encode()).hexdigest()[:40]

// Check: demo@thecompoundeffect.com -> a7dd10d16281b6d4f01adbba751aab21a27dc6b9

If a Champion's email changes, delete the old key record and create a new one. An unknown email gets this message on the page: "Sorry, we couldn't find you today. Please contact Member Services to get your unique referral links." It links to helpme@darrenhardy.com with the subject "I can't access my referral link". Expect those emails to reach Member Services when a key is missing.

3. Board Pages

Collection ID 6ac89043132e0bf5aad97b4a. The searchable full standings list reads plain text from these records so the page makes a few requests instead of hundreds.

  • Records have slugs p1, p2 and so on, about 250 Champions each.
  • Field rows: one Champion per line as rank|name|level|impacts. Level is the number, 0 to 4.
  • The first line of p1 is pages=N, the total number of board pages. The second is levels=Name:min,Name:min,... from the Champion Levels records, lowest first.
  • No pipe characters in names. Replace any with a space.
pages=1
levels=Copper:2,Silver:4,Gold:8,Platinum:16
1|Taylor Richardson|4|18
2|Jeannie Henderson|3|15
...
52|Dan Tripp|0|1

Order of the sync

  1. List existing Champions and Champion Logins (100 per page) and map them by slug.
  2. Calculate every field for every Champion first, then write. Ranks depend on everyone, so never update one Champion on its own.
  3. Create new records and update changed ones, up to 100 items per request. Only send records whose values changed.
  4. Update the Board Pages records.
  5. Publish the changed items: POST /v2/collections/{collection_id}/items/publish with {"itemIds": [...]} for each collection.

Update shape: PATCH /v2/collections/{collection_id}/items with {"items": [{"id": "...", "fieldData": {...}}]}.

Rate limit is 60 to 120 requests a minute depending on plan. On a 429, wait for the Retry-After header and retry. Never delete a Champions record; if someone should come off the board, tell us.

How the board uses the ID

  • From an email or mailer link: https://www.thecompoundeffect.com/champion?id=<referral ID> signs them in. The page also accepts ref, rid or cid.
  • By email: the sign-in box uses Champion Logins as above. After a match the page adds ?id=<referral ID> to the address, so a bookmark keeps them signed in.
  • Share links: every link a Champion copies carries utm_content=<referral ID> (plus ref), matching what your redirect sends to Spiffy.

At launch a Champion can share three things, listed below. This list will change over time as we add and retire offers. Whatever the offer, every share link carries the same referral ID in utm_content, so your sync doesn't need to know which offers exist. It only needs to count what credits an impact.

Before your first sync

The Champions collection holds 52 placeholder records named "Your Name Here". They have no champion-id and random slugs, so they won't clash with your records. Board Pages p1 lists the same placeholders. We remove the placeholders and the DEMO123 test record right before your first live run. You don't need to delete anything.

The placeholders also use our hands-off fields (featured, headshot) to fill the cards at the top of the page. Once real Champions are in, our team picks who is featured.

The code

champion-sync.mjs (sent to you with this spec) is one file, Node 18 or later, no packages to install. It does everything in this spec: ranking, levels, status lines, the weekly move, sign-in keys, Board Pages, rate-limit retries and publishing only what changed.

Your console calls it once after each HubSpot sync with every Champion it knows about:

import { syncChampions } from './champion-sync.mjs';

await syncChampions([
  { referralId: 'ABC123', name: 'Brenda Huntley', email: 'brenda@example.com',
    impacts: 8, lastCreditAt: '2026-11-02T18:04:00Z' },
  // ...every Champion, including those with 0 impacts
], { token: process.env.WEBFLOW_TOKEN });
  • node champion-sync.mjs --selftest checks the rules offline.
  • node champion-sync.mjs champions.json --dry-run reads Webflow and prints what it would change without writing anything. Please do this first and send us the output.
  • The weekly rank snapshot is saved to champion-rank-snapshot.json by default. To keep it in your database instead, pass snapshot: { load, save }.
  • Send the full list every run, not only the changes, because ranks depend on everyone.

Open questions for you

  1. Please confirm what counts as one impact. Only a paid Founders Event enrollment counts: one seat whose Spiffy deal carries the Champion's ID in utm_content. Nothing else credits an impact, including the gift book. When a seat is refunded, does it come back off their count?
  2. ID format. Slugs allow only lowercase letters, numbers and hyphens. Do referral IDs ever contain anything else?
  3. Champions with 0 impacts. We'd like them to have a record so they can sign in and get their links. They would rank at the bottom and stay off the Board Pages. OK?
  4. Timing. Is your hourly sync a good cadence, or can it run on each new deal?
  5. Enroll a leader. The Enroll form on the board is a mockup today. A new investment opens /founders-event#enroll with the Champion's ID. Paying with an existing seat credit isn't wired to anything yet. Should it go to a HubSpot form your sync reads, or straight into Spiffy?
